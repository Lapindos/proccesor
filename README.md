# Марущак Сергей Процессор: рабочий цикл и теория

## Часть 1. Рабочий цикл процессора

Тема: взаимодействие устройств ЭВМ при выполнении машинной команды.

### 1. Программа, команды и память

Программа — это последовательность команд, которая превращает входные данные в результат.

### 2. Представление данных

Числа хранятся в двоичной системе: со знаком, с фиксированной точкой и с плавающей точкой (форматы подробно разбирались в теме АЛУ). Символы хранятся своими двоичными кодами. Двоичные векторы для поразрядных логических операций обычно лежат в беззнаковых целых.

Пример байта со знаком. Старший бит — знак: `0` — число положительное, `1` — отрицательное. Остальные биты — модуль.

### 3. Формат двухадресной команды

Команда — приказ выполнить операцию.

Результат, как правило, записывается **на место первого операнда**.

### 4. Система команд

Конкретные коды берут из справочника процессора.

### 5. Из чего состоит схема

процессор и ОП, соединённые тремя шинами.

**В процессоре:**

| Узел | Зачем нужен |
| --- | --- |
| УУиС | устройство управления и синхронизации. Дирижирует всеми остальными узлами |
| СчАК | счётчик адреса команды. Хранит адрес следующей команды. Длина равна числу бит адреса и зависит от объёма ОП в байтах |
| РК | регистр команд. Хранит выбранную команду всё время, пока она выполняется. Длина — по самой длинной команде |
| АЛУ | считает. Два регистра операндов: **Р1** — аккумулятор (сюда кладут операнд, здесь появляется результат), **Р2** — второй операнд. У АЛУ есть своё маленькое устройство управления |
| ПортА | порт адреса, подключён к шине адреса |
| ПортД | порт данных, подключён к шине данных |
| DC | дешифратор КОП. По коду операции выдаёт осведомительный сигнал `xᵢ = 1` |
| Генератор С | синхросерия для УУиС |

**В оперативной памяти:**

| Узел | Зачем нужен |
| --- | --- |
| РАОП | регистр адреса ОП. Длина равна ширине шины адреса |
| РСОП | регистр слова ОП. Длина равна ширине шины данных |
| ЧтОП | сигнал чтения |
| ЗпОП | сигнал записи |

**Шины:** адреса, данных и управления.

Снаружи процессор выглядит так. На выводы `A` выходит адрес, по `D` ходят данные, `RD`/`WR` — чтение и запись памяти, `IN`/`OUT` — чтение и запись периферии. `RESET` и `SET` включают и выключают УУиС, `CLC` можно посадить на внешний генератор.

### 6. Как процессор читает и пишет память


**Чтение.** Процессор выставляет адрес на шину адреса и даёт сигнал **ЧтОП**. Слово появляется в РСОП и по шине данных приходит в порт данных.

**Запись.** Процессор выставляет адрес в РАОП, данные в РСОП и даёт сигнал **ЗпОП**.

### 7. Пример: сложение чисел с фиксированной точкой
- в системе команд 256 операций, поэтому КОП занимает **8 бит**;
- два операнда в ОП, в команде два адресных поля;
- если операнд длиннее байта, адрес — это адрес первого байта; КОП однозначно задаёт и операцию, и длину операндов;
- память — последовательность байтов, у каждого байта есть адрес;
- шина данных **32 бита** (за одно обращение читается от 1 до 4 байт);
- шина адреса **8 бит**, значит ОП не больше 2⁸ = **256 байт**;
- и команды, и данные лежат в одной памяти — это **принстонская (фон-неймановская)** архитектура.

До начала шага в СК уже стоит адрес текущей команды, в РК ещё лежит предыдущая, в АЛУ — операнд и результат предыдущей команды.

**Шаг 1.** На шину адреса выставляется СК = `00110110` (адрес 54).


**Шаг 2.** По этому адресу из ОП читается команда и попадает в РК. Сигналы чтения и записи процессор выставляет на шине управления в нужные моменты.


**Шаг 3.** Из РК на шину адреса выставляется адрес первого операнда A1 = 118 (`01110110`).



**Шаг 4.** Первый операнд (2 байта) читается в аккумулятор.

**Шаг 5.** На шину адреса выставляется A2 = 120 (`01111000`).

**Шаг 6.** Второй операнд читается во второй регистр АЛУ.

**Шаг 7.** АЛУ выполняет операцию из поля КОП. Здесь это сложение с фиксированной точкой. Результат появляется в аккумуляторе: `01001010 10111111`.

**Шаг 8.** На шину адреса снова выставляется A1, потому что результат пишется на место первого операнда.

**Шаг 9.** Результат уходит по шине данных в ОП. Байты `01001010` и `10111111` оказываются в ячейках 118 и 119.

**Шаг 10.** СК увеличивается на длину команды. Команда была 3 байта, поэтому `54 + 3 = 57`, в счётчике теперь `00111001`.

**Шаг 11.** Цикл начинается сначала уже для следующей команды.

### 8. Откуда процессор знает, что АЛУ закончило

После загрузки операндов и пуска микропрограммы АЛУ ставит на линии **ZАЛУ** единицу: занято. Процессор ждёт, пока там не появится ноль. Ноль значит: микропрограмма кончилась, в Р1 лежит результат, АЛУ свободно и можно писать результат в память.

Шифратор Coder сжимает эти четыре линии в **двухбитный позиционный** код:

| Код РПР | Смысл |
| --- | --- |
| 00 | результат равен 0 |
| 01 | результат меньше 0 |
| 10 | результат больше 0 |
| 11 | переполнение с фиксированной точкой |

Отдельные линии — исключительные ситуации:

| Линия ШАЛУ | Флаг |
| --- | --- |
| 3 | ППФТ, переполнение с фиксированной точкой |
| 4 | ПППор, переполнение порядка |
| 5 | ИПор, исчезновение порядка |
| 6 | ПЗнач, потеря значимости |
| 7 | деление на ноль |
| 8 | ZАЛУ, занято/свободно |

Когда УУиС видит `ZАЛУ = 0`, начинается запись результата. На этом же этапе сохраняются признак и флаги:

- `y8`: ПортД := Р1
- `y11`: **РПР(0:1) := Coder(ШАЛУ(0:3))** — только для `add`, `sub`, `inc`, `dec`, `and`, `or`, `xor`. Остальные команды РПР не трогают
- `y12`: **РФ(0:4) := ШАЛУ(3:7)** — флаги исключений попадают в регистр флагов прерываний
- `y4`: ПортА := A1
- `y9`: ЗпОП

Если `ШАЛУ(3:7) = 00000`, исключительной ситуации не было.

РПР — 2 бита. РФ шире, чем число флагов АЛУ: прерывания приходят ещё от таймеров и внешних устройств.

### 9 Ветвления в программе: как работают команды перехода

В штатном режиме счётчик команд (`СчАК`) просто увеличивается на длину текущей инструкции `L`. Для реализации циклов и логических ветвлений применяются **команды перехода**, принудительно меняющие значение `СчАК`. Ниже разобран алгоритм **условного перехода по маске** с прямой адресацией.

**Структура команды в регистре команд (РК):**

| Поле | Разряды | Назначение |
| --- | --- | --- |
| **КОП** | `0...7` | Код операции |
| **Маска (M)** | `8...11` | Условие перехода (какие биты признака результата проверяем) |
| **Адрес (A)** | `12...27` | Куда переходить (16-битный адрес) |

**Логика выполнения:**

* **Игнорирование (NOP):** если маска `M` или адрес `A` состоят из одних нулей, команда не делает ничего (нет операции).
* **Безусловный прыжок:** если маска полностью состоит из единиц (`1111`), переход выполняется в любом случае.
* **Условный прыжок:** если текущий код признака результата (`РПР`) совпадает с битами маски, осуществляется переход — в `СчАК` копируется адрес `A`.
* Если совпадения нет, программа выполняется дальше линейно.
* Команда перехода не изменяет текущие флаги состояния и не генерирует прерываний.

> **Важный нюанс тайминга:** `СчАК` аппаратно сдвигается на следующую инструкцию **сразу после выборки** команды перехода, еще до проверки условия. Если условие в итоге выполняется, это заранее продвинутое значение просто перезаписывается новым адресом `A`.

**Пример с 16-битной архитектурой:**
Представим систему с **16-битной шиной адреса** (вместо 8-битной из исходной лекции).

* Максимальный объем адресуемой памяти составляет 2¹⁶ байт = **64 КБ**.
* Ширина адреса равна 16 бит.
* Счётчик `СчАК` имеет разрядность 16 бит (биты `0…15`).
* В регистре команд поле `A` занимает 16 бит: с 12-го по 27-й разряд (`12…27`).

**Аппаратная реализация (сигналы управления):**
Для выполнения перехода схема формирует четыре осведомительных сигнала:

* `x1` — проверка на пустую маску: `РК(8:11) == 0000`.
* `x2` — проверка на нулевой адрес: `РК(12:27) == 0`.
* `x3` — проверка на безусловный переход: `РК(8:11) == 1111`.
* `x4` — совпадение маски: аппаратный дешифратор переводит 2-битный `РПР` в унитарный код, накладывает его на биты маски и объединяет результат схемой логического «ИЛИ».

Если срабатывает условие перехода `x4` (или `x3`), генерируется управляющий сигнал **`y1`**, который выполняет микрооперацию:
`СчАК := РК(12:27)`. Адрес из команды становится текущим адресом исполнения.
### 10. Прерывания

Во время программы возникают два вида прерываний.

**Исключения** — из-за самой команды: деление на ноль, переполнение с фиксированной точкой, исчезновение и переполнение порядка, потеря значимости. Их, как правило, **нельзя замаскировать**.

**Внешние** — запрос устройства или нажатие клавиши. Пример с лекции: во время Word нажатие Num Lock зажигает лампочку. Процессор уходит в программу обработки и потом возвращается в Word ровно в то место, где его прервали. Внешние прерывания **можно замаскировать**.

В мультипрограммном режиме каждой программе дают квант времени (на лекции пример τ = 1/30 с). По концу кванта таймер прерывает процессор, и он переключается на другую программу. Квант маленький, поэтому кажется, что программа идёт непрерывно.

Для этого в процессор добавлены:

- **РФ** — регистр флагов прерываний;
- **РМ** — регистр масок;
- **УС** — указатель стека.

Число бит РФ и РМ равно числу причин прерывания: `i`-й бит — `i`-я причина. Если специальной командой поставить `1` в `i`-й бит маски, это прерывание не обработают. Не все причины маскируются.

В начале ОП (в гарвардской архитектуре — в памяти программ) первые `n` слов занимает **таблица векторов прерываний**. Её нельзя занимать своими данными ни в ассемблере, ни в машинных кодах; трансляторы языков высокого уровня её тоже не используют. В `i`-м слове таблицы лежит команда безусловного перехода `JMP Ai` на первую команду обработчика.

Рядом в памяти выделена область стека. Стек работает по принципу **LIFO**: последним вошёл — первым вышел. УС всегда показывает на верхушку, то есть на верхнее свободное слово. Запись идёт по адресу из УС, после неё УС увеличивается. Перед чтением УС уменьшается, и читается то, что положили последним.


После очередной команды процессор смотрит РФ. Если `Fᵢ = 1`:

1. Адрес возврата (СК указывает на ещё не выполненную команду) кладётся в стек:
   - `ОП[УС] := СК`
   - `УС := УС + 1`
2. В СК загружается номер вектора: `СК := i`
3. Исполняется слово таблицы: `JMP Ai`, после чего `СК = Ai`
4. Выполняются команды обработчика
5. Последняя команда обработчика — **RETI** (возврат из прерывания):
   - `УС := УС − 1`
   - `СК := ОП[УС]`

Если единиц в РФ несколько, опрос идёт с учётом приоритетов или без них. Это уже тема курса операционных систем.

Недостаток векторной схемы с лекции: в стеке сохраняется **только адрес возврата**. Если обработчик портит регистры общего назначения или регистры специальных функций (например РПР), программист сам обязан сохранить их на входе и восстановить перед RETI.

Есть системы, которые при прерывании сами сохраняют и потом восстанавливают не только адрес, но и часть специальных регистров. Вместе они называются **словом состояния программы (ССП, PSW)**: туда входят, например, РПР и регистр масок.

## Часть 2. Теория процессора

### 1. Операционный блок

Структурный базис операционного устройства — три вида элементов:

- **регистры** хранят слова;
- **шины** соединяют регистры и пересылают слова;
- **комбинационные схемы** считают по управляющим сигналам от устройства управления.

АЛУ в этом базисе — комбинационная схема без собственной памяти. На два входа приходят операнды (например из двух регистров), на выходе появляется результат. Типовые действия, которые показывает лекция: пересылка `mov R1, R2`, сдвиг `rol R0`, сложение `add R0, R1`.

Операционное устройство может быть собрано вокруг общей магистрали: регистры выставляют слово на шину, комбинационная схема его преобразует, результат возвращается в регистр. Такой блок называют операционным (ОПБ).

Один разряд АЛУ устроен так. Входы `A` и `B` можно пропустить или закрыть (`ENA`, `ENB`) и инвертировать (`INVA`). Логическая часть умеет дать `A·B`, `A+B` и инверсию `B`. Декодер на `F0` и `F1` выбирает, какая из этих функций пойдёт дальше. Полный сумматор складывает выбранное значение со входом переноса и выдаёт бит суммы и выход переноса.


Восемь таких разрядов, соединённых цепочкой переноса, дают восьмиразрядное АЛУ. На вход переноса младшего разряда подают `INC`, когда нужно увеличить число на единицу.


Внутри операционного устройства выделяют отдельные схемы под разные группы операций: целые, логика, сдвиги, десятичная арифметика, плавающая запятая, графика.

### 2. Устройство управления

Устройство управления автоматически ведёт вычислительный процесс. Оно формирует сигналы на каждый шаг:

1. выбрать очередную команду из ОЗУ;
2. расшифровать код операции;
3. сформировать адреса операндов и выбрать операнды;
4. передать операнды в операционное устройство и выполнить операцию;
5. записать результат обратно в ОЗУ;
6. запустить ввод-вывод;
7. отреагировать на запрос прерывания.

Управляющую часть составляют регистр команды, микропрограммный автомат с дешифратором команд и узел прерываний и приоритетов.

Адресную часть составляют операционный узел управления, регистр адреса и счётчик команд. Они формируют адреса команд и адреса операндов.

Автомат бывает двух видов:

- **с жёсткой логикой** — последовательность микрокоманд спаяна в схеме;
- **с программируемой логикой** — последовательность микрокоманд лежит в памяти микропрограмм.

На лекции есть и пример процессора с тремя шинами: отдельная шина может кормить каждый вход АЛУ и забирать результат, так что пересылки между регистрами не мешают друг другу.

### 3. Три архитектуры системы команд

**Стековая.** Память данных — стек, LIFO. Операнды берут с вершины, результат кладут туда же, поэтому в команде часто нет адресов вообще: все данные опознаются по вершине. Глубину стека обозначают `N`. Операции: `push` (положить) и `pop` (снять). Писать можно только в верхнюю ячейку. Аппаратно стек делают набором регистров сдвига или областью памяти с указателем.

**Аккумуляторная.** Один главный регистр — аккумулятор. `load x` читает ячейку `x` в аккумулятор, `store x` пишет аккумулятор в `x`. Команды короткие, декодировать их просто. Минус: регистр один, поэтому к памяти приходится обращаться много раз.

**Регистровая.** Операнд может лежать в памяти или в регистре общего назначения. Три вида команд обработки: регистр-регистр, регистр-память, память-память. Код получается компактным, а счёт идёт быстрее, потому что часть обращений к памяти заменяется обращениями к регистрам. Платой за это — более длинные инструкции, чем у аккумуляторной машины.

У CISC регистров общего назначения немного. RISC держит их много, вплоть до нескольких сотен. Крайний пример с лекции — IA-64 (Itanium): большой регистровый файл, при вызове процедуры регистры переименовываются аппаратно (register stack engine), отдельно есть регистры плавающей точки. На схеме ниже у целых регистров ещё есть разряды NaT — отметка, что значение недействительно.

### 4. Регистр флагов 8086

| Флаг | Имя | Смысл |
| --- | --- | --- |
| CF | Carry Flag | перенос |
| PF | Parity Flag | чётность |
| AF | Auxiliary Carry Flag | вспомогательный перенос (из младшей тетрады) |
| ZF | Zero Flag | результат равен нулю |
| SF | Sign Flag | знак |
| TF | Trap Flag | пошаговая отладка |
| IF | Interrupt-Enable Flag | разрешение внешних прерываний |
| DF | Direction Flag | направление строковых команд |
| OF | Overflow Flag | переполнение |

Это тот же смысл, что у РПР и РФ из первой части, только флаги уже разложены по битам конкретного процессора.

### 5. Группы команд x86

**Пересылки.**

- `MOV` — пересылка общего назначения, например `MOV eax, [ebx]`.
- `PUSH` / `POP` — стек. Указатель `(E)SP` показывает на последний **занятый** элемент. Это другое соглашение, чем в учебной схеме первой части, где УС показывал на свободную верхушку.
- `LEA` — загрузить эффективный адрес, не читая саму ячейку.
- `LDS`, `LES`, `LFS`, `LGS`, `LSS` — загрузить длинный адрес вместе с сегментом.
- Строковые `MOVSB` / `MOVSW` / `MOVSD`. С префиксом `REP`: байт копируется из `DS:[E]SI` в `ES:[E]DI`, оба указателя сдвигаются (вперёд при `DF = 0`, назад при `DF = 1`), `CX` уменьшается, и так пока `CX` не станет нулём. `LODS*` читает строку в `AL`/`AX`/`EAX` (префикс повтора ей не нужен). `STOS*` пишет регистр в строку и с `REP` заполняет блок одним и тем же значением.

**Арифметика.**

- `ADD`, `ADC` (сложение с переносом CF), `SUB`, `SBB` (вычитание с заёмом CF).
- `CMP` — вычитание только ради флагов, результат выбрасывается.
- `NEG` — смена знака в дополнительном коде.
- `INC` / `DEC` — плюс или минус единица; на CF не влияют.
- `MUL` / `IMUL`, `DIV` / `IDIV` — умножение и деление без знака и со знаком. Приёмник произведения и источник делимого вдвое шире операндов.

**Сдвиги.** На 386+ их пять семейств. На сколько сдвигать: на 1, на число из `CL` или на константу в команде.

- `ROL` / `ROR` / `RCL` / `RCR` — циклические. Вышедший бит входит с другой стороны; варианты `*CR` протаскивают бит ещё и через CF.
- `SAL` / `SAR` — арифметические, равносильны умножению или делению на степень двойки. При сдвиге вправо знаковый бит остаётся на месте.
- `SHL` / `SHR` — логические: вышедшие биты теряются, с другой стороны вписываются нули.
- `SHLD` / `SHRD` — сдвиг двойного слова.

**Передача управления.**

- `Jcc` — условные переходы, в x86 их десятки. Простые условия названы по флагам: `JC` (есть перенос), `JNZ` (не ноль). Для чисел со знаком используют `greater` / `less`: больше, меньше, больше или равно, меньше или равно.
- `LOOP` — цикл со счётчиком в `CX`. Вложенные циклы на одном `CX` собирать неудобно.
- `JMP` — безусловный переход.
- `CALL` — вызов процедуры, `RET` — возврат.
- `ENTER` / `LEAVE` — собрать и разобрать стековый кадр.

### 6. Подпрограммы

Программу структурируют двумя способами. Макроподстановка вставляет текст ещё при компиляции. Подпрограмма — это связь по управлению и по данным во время выполнения: надо запомнить контекст и выделить память, а потом её освободить. На уровне системы команд основное средство — аппаратная поддержка вызова.

**Контекст** — всё, без чего программу нельзя продолжить с того же места: счётчик команд, регистр флагов, остальные регистры, указатели стеков ядра и пользователя, указатель адресного пространства (у x86 это `CR3`, каталог таблиц страниц) и промежуточные результаты.

Как контекст сохраняют в разных машинах:

- отдельные команды, у x86 это `PUSHA` / `POPA`: в стек идут `(E)AX`, `(E)CX`, `(E)DX`, `(E)BX`, `(E)SP`, `(E)BP`, `(E)SI`, `(E)DI`, причём в стек пишется значение `SP` **до** самой команды;
- несколько комплектов регистров или окно регистров в памяти (TMS9900: регистров как таковых нет, рабочую область задаёт указатель);
- стек из трёх регистров у Transputer: переход возможен только при пустом стеке, поэтому хранить почти нечего, кроме адреса возврата;
- аппаратное переименование регистрового файла при вызове (IA-64).

Команда вызова (`CALL`, `JSR`) обязана сама запомнить адрес возврата — адрес команды, которая стоит сразу за `CALL`, — и загрузить в счётчик команд адрес первой команды подпрограммы. Возврат (`RET`, `RTS`) достаёт этот адрес обратно.

Данные в подпрограмму передают тремя способами: сами значения, если их мало или регистров много; через стек; через заранее оговорённое место в памяти (в некоторых машинах это слова сразу за командой вызова).

Вложенные вызовы на примере с лекции: `main` вызывает `proc1`, та вызывает `proc2`, та вызывает `proc3`. У каждой процедуры свои локальные переменные, и каждый вызов получает собственный кадр.

Стековый кадр x86 состоит из трёх частей:

- указатель на начало предыдущего кадра (динамическая связь);
- таблица указателей на кадры объемлющих процедур (индикатор);
- локальные переменные.

`BP` показывает на начало кадра, на старший адрес. Команда `ENTER frmsiz, level` делает кадр так:

1. запомнить текущий `SP` — это будет начало нового кадра;
2. записать `BP` в стек — динамическая связь;
3. `(level − 1)` раз скопировать в стек элементы индикатора из предыдущего кадра;
4. положить в стек запомненный `SP` — ссылка на этот кадр в индикаторе;
5. `BP :=` запомненный `SP`;
6. `SP := SP − frmsiz` — место под локальные переменные.

`level` — уровень вложенности; у самой внешней процедуры он равен 1. `LEAVE` делает обратное: восстанавливает `SP` и `BP`.

По статистике, которую приводят на лекции, глубокая вложенность редка: только 1,25 % процедур имеют больше шести параметров, только 6,7 % — больше шести локальных переменных, а цепочки вызовов длиннее шести почти не встречаются. Поэтому окно регистров и неглубокий стек кадров на практике хватает.

### 7. Память DOS, которая упомянута в той же лекции

Это уже не устройство процессора, а то, как старые системы обходили границу 640 Кбайт. В конспекте оставлено, потому что слайд стоит в том же материале.

- **EMS** (Expanded Memory Specification) — отображаемая дополнительная память, её ведут драйверы EMM, QEMM, `EMM386.EXE`.
- **XMS** (Extended Memory Specification) — память выше 640 Кбайт, драйвер `HIMEM.SYS`. `DOS=HIGH` загружает DOS в верхнюю память.
- **UMB** — блоки верхней памяти, `DOS=HIGH,UMB`.
- **Shadow RAM** — теневое ОЗУ: медленное ПЗУ копируют в быструю оперативную память и дальше читают оттуда.
